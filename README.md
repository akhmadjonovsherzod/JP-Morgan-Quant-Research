# Credit Risk Analytics Platform

An end-to-end credit risk platform: a trained model predicts probability of
default (PD) for a borrower, a FastAPI service scores borrowers and stores
results in PostgreSQL, a small web dashboard makes that usable without
touching `/docs` or raw JSON, and a Power BI star schema turns the scored
portfolio into a 4-page BI report.

Built on 10,000 loan records from the original quant research notebooks,
extended with a production-style data and app layer.

---

## What changed in this pass

The project worked, but three things made it feel unfinished:

1. **`/predict` returned raw JSON with no way to read it.** There's now a
   real dashboard at `/` — a form to score a borrower and a live portfolio
   view, both in plain language instead of a JSON blob.
2. **The API wasn't using the trained model.** It scored every borrower with
   a hand-written formula that lived only in `api/app.py`. It now loads the
   actual Logistic Regression model trained in `model/train_model.py`
   (same approach as `task-3.ipynb`, cleaned up), so the number you see in
   the dashboard is the number the model actually produced.
3. **Power BI only really supported 3 pages.** `dim_date` was created but
   never populated, and there was no way to check the model's predictions
   against what actually happened. The star schema now carries the actual
   outcome per borrower, which supports a 4th **Model Performance** page
   (confusion matrix, accuracy/precision/recall, calibration by rating).

There's also one fixed bug worth flagging: the Dockerfile referenced
`../requirements.txt`, which doesn't exist relative to the Docker build
context — the image would have failed to build. It's now `requirements.txt`.

## How to run

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Start PostgreSQL

Either with Docker:

```bash
docker run -d --name pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=quant_research -p 5432:5432 postgres:15
```

...or point `DB_HOST` in `.env` at a Postgres instance you already have running.
Copy the example env file first:

```bash
cp .env.example .env
```

### 3. Create the schema and load the data

```bash
psql -h localhost -U postgres -d quant_research -f database/init.sql
python database/load_data.py
```

### 4. Train the model

```bash
python model/train_model.py
```

This writes `model/credit_model.joblib` and prints accuracy / F1 / ROC-AUC
to the console.

### 5. Run the app

```bash
uvicorn app.main:app --reload
```

Open **http://localhost:8000** — that's the dashboard. Score a borrower on
the left, and click **Score all loans** in the portfolio panel to populate
the insights (rating breakdown, top-risk table, KPIs). The FastAPI docs are
still available at `/docs` if you want to hit the API directly.

### Or: run everything with Docker Compose

```bash
cd docker && docker-compose up -d
python ../model/train_model.py   # model file is mounted into the container via the code copy
python ../database/load_data.py
```

## Power BI

1. Score the portfolio first (via the dashboard's "Score all loans" button,
   or `python score_loans.py`).
2. Build the star schema:
   ```bash
   psql -h localhost -U postgres -d quant_research -f powerbi/star_schema.sql
   ```
   This is safe to re-run any time you rescore the portfolio — it rebuilds
   the dimension and fact tables from scratch.
3. Open `powerbi/quant-research.pbix` in Power BI Desktop and hit **Refresh**.
4. Measures and recommended visuals for all 4 pages are in
   `powerbi/DAX_measures.md`, including the new **Model Performance** page
   (confusion matrix, accuracy/precision/recall, PD vs. actual default rate
   by rating band).

## The model

`model/train_model.py` trains a `StandardScaler → LogisticRegression`
pipeline on the same feature set explored in
`Quant-Research-main/Task 3 - Credit risk analysis/task-3.ipynb`, with two
small, deliberate differences:

- `customer_id` is dropped from the features. It's an identifier, not a
  risk signal — the notebook included it in `X` by accident (`X =
  Loans_df.drop(['default'], axis=1)` keeps everything else).
- `debt_to_income` and `loan_to_income` are added as engineered features,
  which the notebook's own EDA showed were informative.

On a held-out 20% test split: **99.8% accuracy, 0.995 F1, 1.00 ROC-AUC** —
in line with what the notebook found. Expected loss uses a 10% recovery
rate (`expected_loss = prob_default × 0.90 × loan_amt_outstanding`), matching
the assumption used in the notebook rather than the API's old value, which
had drifted to 45%.

## Dataset

| Feature | Description |
|---|---|
| `customer_id` | Unique borrower identifier |
| `credit_lines_outstanding` | Number of active credit lines |
| `loan_amt_outstanding` | Current outstanding loan balance |
| `total_debt_outstanding` | Total outstanding debt |
| `income` | Annual income |
| `years_employed` | Years of employment |
| `fico_score` | FICO credit score |
| `default` | Target variable (1 = defaulted, 0 = not defaulted) |

**10,000 records, ~18.5% default rate.**
